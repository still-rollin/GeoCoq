# Reproducing the GeoCoq → Lean 4 Translation

A self-contained guide to building, verifying, and re-running the
structure-preserving translation of `Elements/OriginalProofs` from GeoCoq (Coq) to
Lean 4. Intended for the GeoCoq authors and anyone who wants to reproduce the
result from scratch.

**Result to reproduce:** `Elements/OriginalProofs` — **229 / 234 lemmas proven in
Lean 4, clean rebuild, zero `sorry`-holes**, with 5 documented Tier-4 residuals.
Full methodology in [`docs/methodology_paper.md`](methodology_paper.md).

---

## 0. Install (zip overlay)

This is delivered as a zip that **overlays onto a stock GeoCoq checkout**. From
the root of your GeoCoq repository:

```bash
cd /path/to/GeoCoq          # your existing GeoCoq checkout
unzip geocoq-lean-translation.zip   # adds geocoq-lean/, lean/geocoq_translate/, docs/
```

It adds new files only and overwrites six `theories/Elements/OriginalProofs/*.v`
with versions carrying tiny (1–2 line) annotations needed for faithful
re-transpilation. Nothing else in your `theories/` is touched.

## 1. What's in the delivery

Everything lives inside the GeoCoq repository tree (you already have `theories/`).
Three additions:

| Path | What it is | Hand-written or generated |
|---|---|---|
| `geocoq-lean/` | The transpiler + drivers (Python) | hand-written |
| `lean/geocoq_translate/` | The Lean 4 output package | **mixed** (see below) |
| `docs/methodology_paper.md`, `docs/REPRODUCE.md` | Write-up + this guide | hand-written |

Inside `lean/geocoq_translate/GeocoqTranslate/`:

```
Euclidean/Axioms.lean                          ← hand: axiom typeclass hierarchy
Elements/OriginalProofs/
  euclidean_defs.lean                          ← hand: ~25 derived definitions
  euclidean_tactics.lean                       ← hand: ported tactic vocabulary
  Lemmas/lemma_*.lean, proposition_*.lean      ← GENERATED by the transpiler
```

> **Key idea:** the four hand-written files are the *foundation*; every
> `lemma_*.lean` is regenerated by `geocoq-lean/geolean_transpile.py` from the
> corresponding `theories/Elements/OriginalProofs/*.v`. A handful of genuinely
> hard lemmas are hand-written and protected (the `HANDMADE` set in
> `fresh_euclidean.py`). See the paper, Part II §B.

## 2. Prerequisites

| Tool | Version | Notes |
|---|---|---|
| **elan** (Lean toolchain manager) | latest | installs Lean automatically |
| **Lean 4** | `leanprover/lean4:v4.30.0` | pinned in `lean-toolchain`; elan fetches it |
| **Lake** | bundled with Lean | the build tool |
| **Mathlib** | pinned in `lake-manifest.json` | dependency; use the cache (below) |
| **Python** | ≥ 3.9 | for the transpiler/drivers (stdlib only, no pip installs) |

Install elan (if not present):

```bash
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh
```

You do **not** need Coq/Rocq to *build* the Lean side. Coq is only needed if you
want to (a) regenerate from `.v` sources, or (b) run the optional oracle.

## 3. First build (do this once)

```bash
cd lean/geocoq_translate

# 1. fetch the pinned Mathlib + toolchain
lake update           # resolves lake-manifest.json (already pinned)

# 2. download prebuilt Mathlib oleans — STRONGLY recommended, saves ~1 hr
lake exe cache get

# 3. build the whole translated corpus
lake build
```

The default target is the root `GeocoqTranslate.lean`, which re-exports
`FreshElements` (every translated lemma). The first `lake build` after a cache hit
compiles only the GeoCoq translation (foundation + 234 lemma files), not Mathlib —
a few minutes on a modern machine.

> **Expected:** `lake build` builds **229 lemmas successfully and reports errors on
> exactly 5 files** — `lemma_8_3`, `lemma_fiveline`, `lemma_collinear4`,
> `lemma_tarskiparallelflip`, `proposition_22`. These are the **documented Tier-4
> residuals** (Part I §5.2 of the methodology paper), *not* a broken build. Seeing
> precisely those five errors **is** the success criterion. For the formal
> coverage report, use the audit in §4.

> If `lake exe cache get` is unavailable for your Mathlib revision, `lake build`
> will compile Mathlib from source (slow, ~30–60 min, one-time).

## 4. The honest coverage measurement

A plain `lake build` reuses cached `.olean` files, which can *mask* broken lemmas
behind stale caches. The trustworthy number comes from a **clean rebuild**. The
driver `fresh_euclidean.py` does exactly this: re-transpiles every lemma from the
`.v` sources, rebuilds from scratch, and parses the log into a coverage report.

```bash
# from the repo root
cd lean/geocoq_translate

# wipe ONLY the Elements oleans (keep Mathlib's cache!)
find .lake/build/lib -path "*Elements/OriginalProofs*" -name "*.olean" -delete

# re-transpile all + clean rebuild + print coverage
python3 ../../geocoq-lean/fresh_euclidean.py
```

Expected tail of the output:

```
========== FRESH EUCLIDEAN COVERAGE ==========
total lemmas            : 234
compiled (no own error) : 229  (97%)
  of which transpiled clean : 211
  of which needed sorry-fb  : 18
own-error failures      : 5
  clean-transpile but failed: ['lemma_8_3', 'lemma_fiveline',
                               'lemma_tarskiparallelflip', 'proposition_22']
build exit code         : 1
```

### Reading the report honestly

- **`compiled (no own error)` = 229** — lemmas that built with no error citing
  their own file.
- **`needed sorry-fb` = 18 is *not* 18 holes.** It is the bucket
  *compiled − transpiled-clean*, which lumps together the hand-written `HANDMADE`
  proofs (complete) and partial-transpile files that still compiled cleanly. The
  **true number of `sorry`-holes is zero** — verify directly:

  ```bash
  cd GeocoqTranslate/Elements/OriginalProofs
  grep -rlw sorry Lemmas/*.lean *.lean      # → only the residual files, if any
  ```

- **5 own-errors** are the documented Tier-4 residuals (`8_3`, `fiveline`,
  `collinear4`, `tarskiparallelflip`, `proposition_22`). Causes and fix-routes are
  in the paper, Part I §5.2.

## 5. The `sorryAx` certification (the real "proven" gate)

"Compiles" is necessary but not sufficient — confirm no `sorryAx` leaks into a
lemma's axiom profile. For any lemma:

```lean
-- in a scratch Lean file, or via the lean-lsp `lean_verify` tool
#print axioms GeocoqTranslate.Elements.lemma_collinearorder
```

A proven lemma should depend only on the GeoCoq axioms (the
`euclidean_neutral*` typeclass fields) and Mathlib/`Classical` — **not** `sorryAx`.

## 6. Translating a single lemma (to inspect the transpiler)

```bash
# from repo root
python3 geocoq-lean/geolean_transpile.py \
    theories/Elements/OriginalProofs/lemma_collinearorder.v \
    lemma_collinearorder \
    -o /tmp/out.lean
cat /tmp/out.lean
```

This shows the structure-preserving output: each Coq `assert (X) by (conclude L)`
becomes `have : ⟦X⟧ := by conclude L`, line-for-line. Compare side-by-side with the
`.v` source to see the 1:1 correspondence.

## 7. Where to look / change things

| You want to… | Edit |
|---|---|
| Change how a Coq tactic maps to Lean | `geocoq-lean/geolean_transpile.py` (`translate_tactic`, `parse_proof`) |
| Strengthen the `conclude`/`conclude_def`/… macros | `lean/.../OriginalProofs/euclidean_tactics.lean` |
| Add/adjust a derived definition | `lean/.../OriginalProofs/euclidean_defs.lean` |
| Protect a hand-written lemma from regeneration | `HANDMADE` set in `geocoq-lean/fresh_euclidean.py` |
| Understand a residual | `docs/methodology_paper.md` Part I §5.2 |

---

## 8. Reproducibility contract

The whole point of the architecture: the corpus is reproducible from
**Coq source + transpiler + hand foundation**. Running §4 on a clean checkout
must regenerate every `lemma_*.lean` and yield the same 229/234. The only
non-regenerated files are the four foundation files and the `HANDMADE` set — all
hand-written and version-controlled.

If a number differs from 229, first re-check that Mathlib's cache is intact
(`lake exe cache get`) and that you wiped *only* the `Elements/OriginalProofs`
oleans, not Mathlib's — measuring against a partial Mathlib rebuild can stall the
build and skew the log.

## 9. Quick-start checklist

```bash
# 0. prerequisites: elan + python3.9+
# 1. build
cd lean/geocoq_translate
lake update && lake exe cache get && lake build      # corpus type-checks

# 2. honest coverage
find .lake/build/lib -path "*Elements/OriginalProofs*" -name "*.olean" -delete
python3 ../../geocoq-lean/fresh_euclidean.py          # → 229/234

# 3. confirm zero holes
cd GeocoqTranslate/Elements/OriginalProofs
grep -rlw sorry Lemmas/*.lean *.lean                  # → residuals only
```
